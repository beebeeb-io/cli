### First-failure persistence correction

The initial bound-only persistence decision above is too narrow for L7c: a first pass can open L6 custody, then fail content authentication before D-L1 permits `account_id` to be written. That observation must still survive. Keep a separate `custody_account_id` for the custody fact only, verified against `/auth/me` before restoring it. Retain `custody_seen` even on a failed first pass; continue to write `account_id` only after successful sync, and persist no pending envelopes or canonical opaque key metadata until then. A changed custody account discards the old observations. This does not grant sync authority or change D-L1's mismatch refusal. Add a red-first regression before implementing this correction.
- First-failure red: `first-failure-red.log`, 0 passed / 1 failed (missing custody-account observation after a failed content open).
- First-failure green: `first-failure-green.log`, 19 passed / 0 failed (custody 7, shared-folder sync 8, D-L1 binding 4). A failed first sync keeps `account_id` absent and `owned_keys` empty, persists the verified-account custody fact, then a second process rejects a legacy 404 replay with zero mutations. A different unbound custody-account ID discards the old memory and remains legacy-compatible.
